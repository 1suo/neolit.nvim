*neolit.nvim* *neolit*

Neovim companion for the Git-native Neolit planning workspace.

==============================================================================
INSTALLATION                                                     *neolit-install*

Requirements:
- Neovim 0.10+
- Node.js 22.12+
- Node.js 22.12+ and npm. The lazy.nvim build step installs and builds the core automatically.

Install 1suo/neolit.nvim with your plugin manager. Example lazy.nvim spec:

  {
    "1suo/neolit.nvim",
    build = "npm install",
    dependencies = {
      {
        "olimorris/codecompanion.nvim",
        dependencies = { "nvim-lua/plenary.nvim", "nvim-treesitter/nvim-treesitter" },
        opts = {
          interactions = {
            chat = { adapter = "opencode" },
          },
        },
      },
    },
    opts = {
      comparison_base = "HEAD",
      node = "node",
      journal_dir = "~/Documents/memo/journal",
      todo_file = "TODO.md",
      spec_file = "SPEC.md",
      codecompanion = { adapter = "opencode" },
    },
    keys = {
      { "<leader>nn", "<cmd>Neolit<cr>", desc = "Open Neolit workspace" },
    },
    cmd = { "Neolit", "NeolitPlan", "NeolitClose" },
  }

CodeCompanion is installed and configured by this spec. Its setup is essential:
without opts (or config) lazy.nvim can install the plugin without registering
commands such as :CodeCompanionChat. The example selects OpenCode over ACP;
the opencode executable must be available on PATH and already configured.

==============================================================================
CONFIGURATION                                                     *neolit-config*

Call require("neolit").setup(opts), or provide opts through your plugin manager.

  {
    node = "node",             -- Node.js executable
    directory = nil,           -- repository; defaults to cwd
    comparison_base = "HEAD",  -- Git comparison base
    codecompanion = {
      adapter = "opencode",    -- CodeCompanion adapter used by chat_open
    },
    keymaps = {
      open_workspace = "<leader>nn",
      -- Override individual actions by action name.
    },
  }

The plugin build step installs and builds the core dependency inside the plugin. No global install, second checkout, or core path configuration is required.

Keymap overrides are per action. Set an action to false or "" to disable it.
Unspecified actions keep their defaults. The full action list is in
|neolit-keymaps|.

==============================================================================
COMMANDS                                                           *neolit-commands*

:Neolit
    Open the planning workspace for opts.directory or the current directory.

:NeolitPlan
    Alias for :Neolit.

:NeolitClose
    Close the current Neolit workspace.

:NeolitJournal
    Open the current monthly journal Markdown file.

:NeolitCaptureJournal
    Capture a timestamped entry under today’s journal heading.

:NeolitCaptureTask
    Capture a Markdown checkbox task in todo_file.

:NeolitCaptureRequirement
    Capture the next R-NN requirement in spec_file.

:NeolitCaptureCriterion
    Capture the next AC-NN acceptance criterion in spec_file.

==============================================================================
WORKSPACE                                                          *neolit-usage*

Open Neolit from the repository being inspected with :Neolit or the default
<leader>nn mapping. The workspace uses a 36-column tree on the left and the
current window as its right-hand source preview. Reopening focuses the existing
workspace rather than opening another tree.

Tree navigation:
- <CR> opens the selected source or expands the selected tree node.
- `o` opens the selected file in the preview pane; `F` toggles the selected tree node; `h` / `l` collapse/expand or move to the parent.
- za / zo / zc toggle, open, or close the selected node.
- zr / zm open or close one visible level.
- zR / zM expand or collapse all.
- <leader>nv opens the composed task/requirement view.
- <leader>ns opens the selected task's focused scope.
- <leader>nf toggles affected-only paths.
- <leader>nr refreshes Git and planning data.
- <leader>n? shows context-sensitive key hints.
- `q` closes the workspace.

The composed view links SPEC requirements, TODO tasks, acceptance criteria,
file hints, and current Git changes. From a TODO document, <leader>nv starts
with tasks; from a SPEC document, it starts with requirements. In the composed
view, za expands/collapses a task or requirement and <leader>nv switches
between task and requirement projections.

Planning documents remain ordinary editable Markdown. Derived annotations and
states are based on parsed planning data and Git metadata. File hints are not
proof of implementation; verification requires matching evidence for the
current base and diff.

==============================================================================
CAPTURE AND JOURNAL                                               *neolit-capture*

The journal is stored as monthly Markdown files in journal_dir. Each file uses
daily level-two headings and timestamped entries. todo_file and spec_file are
repository-relative paths; their configured files are loaded even when they
are not linked from README. Other linked TODO/SPEC documents remain discoverable.

Default mappings:
- <leader>nj captures a journal entry.
- <leader>nJ opens the current monthly journal file.
- <leader>nt captures a TODO checkbox.
- <leader>nR captures the next R-NN requirement.
- <leader>nA captures the next AC-NN acceptance criterion.

Capture buffers save with Ctrl-S or :write and cancel with Ctrl-C. Captured
TODO tasks still need explicit SPEC references; acceptance criteria should
name their applicable R-NN requirement IDs.

==============================================================================
CONTEXT COMPOSITION                                                *neolit-context*

The context composer collects literal source excerpts, planning entries,
changed-file diffs, and exact hunks. It does not generate a prompt and does not
send a message by itself.

- <leader>na adds the selected source chunk or change/hunk.
- <leader>np opens the context review view.
- In context review, <leader>n- removes the selected item.
- <leader>ny copies the assembled context.
- <leader>nc clears the context.
- <leader>nM adds the composed context to the active CodeCompanion chat.
- <leader>nx copies selected text.
- <leader>nl copies the selected source path and line, when available.

Captured source ranges and diffs are revalidated before copying or chat
insertion. Stale content is rejected rather than silently replaced. Unsaved,
modified planning buffers must be written before their content can be added.

==============================================================================
CODECOMPANION                                                      *neolit-agent*

CodeCompanion owns the chat interface, ACP transport, session lifecycle,
streaming, permissions, diff presentation, and review actions. Neolit does not
keep a parallel conversation or session store.

Set codecompanion.adapter to the adapter name configured in CodeCompanion.
The default is "opencode". OpenCode sessions can be resumed with CodeCompanion's
/resume command.

- <leader>nm opens CodeCompanion chat with the configured adapter.
- <leader>nM adds the Neolit context composition to the active chat.
- <leader>ne invokes :CodeCompanionCodeReview.
- <leader>nC invokes :CodeCompanionChat Changes.

The CodeCompanion Changes list tracks CodeCompanion tool/ACP edits observed
during the current Neovim session. Neolit's Git view independently discovers
repository changes, including external CLI agent edits.

Use CodeCompanion for diff review. Neolit supplies Git-wide change discovery,
affected-only filtering, and task/requirement/hunk attribution. Selecting a
changed file or hunk navigates to its working-tree source.

==============================================================================
DELETE A PLANNING ENTRY                                           *neolit-delete*

In the tree or a composed view, select a TODO task, SPEC requirement, or
acceptance criterion and press <leader>nD. Neolit removes that complete parsed
entry from its Markdown source. It rejects unsafe paths and modified source
buffers; write the buffer before deleting. This mapping is not installed in
ordinary source-file buffers.

==============================================================================
TASK FIELDS                                                       *neolit-task-fields*

Description:
    Task intent and desired outcome.

Agent notes:
    Actual implementation summary, rationale, deviations, or caveats. This is
    not verification evidence.

Set any keymaps.<action> to false or "" to disable it. Workspace entry, CodeCompanion chat, review, agent changes, and current-file
linking are global mappings. Tree navigation/filter/refresh/delete/copy actions
are tree-local; task/context actions are available in composed views where
their selection makes sense. Ordinary source buffers keep native mappings.

Commands are also available in their applicable Neolit buffers:
:NeolitCompose, :NeolitOpen, :NeolitOpenFile, :NeolitFilter, :NeolitRefresh,
:NeolitDelete, :NeolitCopyText, :NeolitCopyPath, :NeolitToggle, :NeolitChat,
:NeolitChatFile, :NeolitAgentChanges, and :NeolitReview in the tree;
:NeolitContextAdd, :NeolitContextRemove, :NeolitContextCopy,
:NeolitContextClear, :NeolitContextReview, and :NeolitChatContext in composed
views.

Native vertical movement remains native (j/k). The default h/l mappings expand
or collapse the selected tree node; F toggles it. These are buffer-local and
can be remapped or disabled. Fold keys can be remapped through
keymaps.tree_fold_toggle, tree_fold_close, tree_fold_open, tree_expand_level,
tree_collapse_level, tree_expand_all, and tree_collapse_all.
